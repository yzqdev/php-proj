# Git 与危险操作安全规则

在修改当前项目时，必须保护现有 Git 历史、工作区修改和用户数据。

## 严格禁止

任何情况下都不得主动执行以下操作：

-   `git reset --hard`

-   `git reset --merge`

-   `git checkout -- <file>`

-   `git restore <file>`（可能覆盖用户修改时）

-   `git clean -fd`

-   `git clean -fdx`

-   `git clean -fxd`

-   `git push --force`

-   `git push -f`

-   `git push --force-with-lease`

-   `git branch -D`

-   `git rebase`（可能改写已有提交历史时）

-   `git commit --amend`（已有提交已经存在并可能被用户使用时）

-   `git reflog expire`

-   `git gc`

-   删除或覆盖用户未提交的修改

-   删除用户创建但尚未提交的文件

-   批量覆盖、移动或删除项目文件而没有确认

-   执行可能导致数据丢失的清理、重置、回滚操作

## Git 操作原则

1.  默认认为工作区中的所有修改都属于用户，除非能够确认是当前任务产生的修改。

2.  开始任务前先检查：

    -   `git status`

    -   `git diff`

    -   `git diff --cached`

3.  不得为了让项目恢复到“干净状态”而回退、清理或覆盖用户修改。

4.  不得为了修复当前问题而修改、删除或重写已有 Git 历史。

5.  不得执行 force push。

6.  不得执行任何形式的远程分支强制覆盖。

7.  如果发现 Git 状态复杂、存在冲突或无法判断文件归属，应停止危险操作，并向用户说明情况。

8.  如果确实需要执行具有破坏性的 Git 操作，必须先明确说明：

    -   将执行什么操作

    -   哪些文件/提交可能受到影响

    -   为什么普通的非破坏性方案无法解决

    -   等待用户明确授权后才能执行

## 推荐替代方案

需要撤销修改时，优先使用：

-   查看：`git diff`

-   临时保存：`git stash push`

-   创建备份分支：`git switch -c backup/...`

-   创建临时补丁：`git diff > backup.patch`

-   恢复单个明确属于 Agent 自己修改的文件时，先确认文件归属，再进行恢复

永远优先选择可逆操作，而不是不可逆操作。

## Shell 安全

不得为了方便直接执行来源不明的脚本、下载后立即执行的脚本或包含大量删除操作的命令。

执行以下类型命令前必须特别谨慎：

-   `Remove-Item`

-   `del`

-   `rd`

-   `rmdir`

-   `Format-*`

-   `Clear-*`

-   `rm -rf`

-   `chmod`

-   `chown`

-   批量移动/覆盖文件

-   修改系统配置

-   修改防火墙规则

-   修改服务

-   修改注册表

PowerShell 中尤其禁止使用可能递归删除整个目录的命令。

## 最重要的原则

宁可暂停任务并请求用户处理，也不要通过危险操作“强行解决问题”。

任何不确定是否会造成数据丢失的操作，都按照危险操作处理。
